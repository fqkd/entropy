# Macropad: названия локальных задач Codex (Windows, экспериментальная версия)

Эта сборка Entropy работает с прошивкой `codex_entropy` из ветки
[`codex/macropad-native-windows`](https://github.com/fqkd/vial-qmk/tree/codex/macropad-native-windows).
Обе части должны поддерживать протокол MPT1. Старые прошивки продолжат работать
с редактором раскладки, но не получат названия задач.

## Запуск

1. Прошейте Macropad rev3 соответствующим UF2. Сброс EEPROM не требуется;
   перед обновлением полезно экспортировать свою раскладку из Entropy.
2. Закройте предыдущий экземпляр Entropy и запустите `entropy.exe` из этой сборки.
3. Выберите Macropad. В настройках клавиатуры откройте **Live-интеграции**
   и включите **Codex** под строкой **Синхронизация раскладок**.
4. Откройте настольный Codex. Оставьте Macropad выбранным в Entropy;
   Entropy можно свернуть в трей. Переключитесь на слой Codex на устройстве.

Шесть верхних физических клавиш открывают строки 1–6. Поворот энкодера
перемещает тонкую рамку; нажатие открывает задачу в Codex из текущей программы.
Вращение захватывается аппаратными прерываниями, в том числе во время обновления
дисплея. Один полный щелчок — одна строка, без ускорения. Неизменившиеся строки
больше не перерисовываются постоянно.
Длинное название сначала сокращено; на выбранной строке через 0,8 секунды
начинается прокрутка. Кириллица поддерживается шрифтом прошивки; символы,
которых нет в шрифте (например, многие emoji), могут отображаться квадратами.
Передаётся до 96 байт UTF-8 на название без разрыва символов.

## Как формируется список

Entropy читает локальную базу `%USERPROFILE%\.codex\state_5.sqlite`
только для чтения (либо каталог `CODEX_HOME`, если задан).
Берутся шесть последних неархивных локальных задач без подагентов.
Новые для экрана задачи появляются сверху; существующие строки сдвигаются
вниз, сохраняя взаимный порядок. Изменение статуса или названия показанной
задачи само по себе не перемещает её. Если сразу появились несколько задач,
они добавляются сверху в порядке давности активности, начиная с самой свежей.
Ранее скрытая задача, вернувшаяся в шестёрку последних, тоже появляется сверху.
При вращении или нажатии смена состава откладывается на 3 секунды после
последнего действия. При новом подключении список берётся в порядке давности
активности. Всего на экране по-прежнему не более шести задач.
Названия, ID и состояния заменяются на устройстве целиком. Нажатие содержит
поколение списка; Entropy открывает ID именно из этого поколения.

Это самостоятельный список Entropy. Его порядок может отличаться от
**Most recent chats** и закреплённых задач в настройках Codex Micro.
Облачные чаты в эту версию не входят. API модели не вызывается, запросы
к модели не создаются, токены на обновление списка не расходуются.

## Цвета и ограничения состояний

- Ярко-синий `#38A8FF`: в локальном журнале обнаружено начало работы.
- Зелёный `#36ED95`: обнаружено завершение, результат ещё не открыт.
- Красно-розовый `#FF5270`: обнаружена отмена.
- Серо-синий: результат открыт либо состояние неизвестно; пустая строка обозначается тире.

При переходе известной задачи в новое рабочее состояние её строка и все
12 RGB-светодиодов мигают пять раз. Основной цвет и яркость по-прежнему
задаются в Entropy. Первое получение списка не вызывает мигания.
После пяти вспышек зелёная заливка строки и подсветка соответствующей клавиши
остаются до открытия задачи с макропада. Выбор рамкой не снимает уведомление. Открытие
клавишей или нажатием энкодера снимает его; повторное завершение этой же задачи
создаёт новое уведомление. Отметки открытых результатов сохраняются в
`%APPDATA%\entropy\codex_task_reads.json` и переживают перезапуск Entropy.

Открытие задачи мышью не снимает зелёную подсветку: для этого откройте её
кнопкой или нажатием энкодера макропада. Entropy больше не открывает
`.codex-global-state.json` и его резервную копию. Это устраняет найденный
конфликт с заменой файла в Windows, вызывавший ошибку `EPERM ... rename`
при отправке сообщений Codex. Даже короткое чтение с разрешённым совместным
доступом оставляет окно для такой ошибки, поэтому чтение убрано полностью.

Для этого исправления нужно обновить только `entropy.exe`; прошивка из комплекта
от 01.10.2026 v2 подходит. Полностью выйдите из старой Entropy через меню трея,
затем запустите новую и включите **Live-интеграции → Codex**. Служебный процесс
`entropy.exe --entropy-hid-proxy` — нормальная часть приложения, не второй экземпляр.

Состояния определяются по событиям локального журнала, а не официальному
живому каналу состояния приложения. Ожидание разрешения в этой версии
отдельно не распознаётся. Если у «работающей» задачи журнал не обновлялся
120 секунд, показывается неизвестное состояние. Внутренняя схема Codex может измениться;
при ошибке чтения Entropy выводит причину в Live features и отключает режим.
При запуске Entropy посреди длинной задачи её статус может сначала быть
неизвестен: анализируется ограниченный конец журнала. Если между опросами
появился слишком большой объём данных, рабочий статус сбрасывается
в неизвестный, пока не найдено новое явное событие. Уже полученное уведомление
о завершении сохраняется до открытия или нового явного запуска/отмены задачи.

В режиме названий кнопки **NO/YES/SEND/NEW/MIC**, назначенные на native Micro
действия, временно отключены: Micro обращается к своему списку, который
может не совпасть с отображаемым. Переключение слоёв, обычные переназначенные
клавиши и другие слои продолжают работать. Чтобы вернуть все native Micro
действия, выключите опцию названий в Entropy.

При закрытии Entropy, выборе другой клавиатуры или потере связи прошивка
возвращает штатный режим Micro с номерами задач (не позднее 6 секунд).
Одновременно следует запускать один экземпляр Entropy.

После сна Windows или потери USB-связи Entropy автоматически переоткрывает
Macropad и заново отправляет названия и статусы. Это работает и когда Windows
сохраняет прежний путь устройства. Пока устройство недоступно, подключение
повторяется с паузой; другая клавиатура не выбирается вместо Macropad.
Восстановление USB включено при активной интеграции Codex. Обновляется только
Entropy, перепрошивка для этого исправления не требуется.

## Проверка на устройстве

Сначала сравните заголовки строк с шестью недавними локальными задачами.
Из Блокнота проверьте каждую из верхних шести клавиш, затем поворот и нажатие
энкодера. Во время работы задачи убедитесь в смене синего на зелёный и пяти
одновременных вспышках RGB. Переименуйте задачу и проверьте новое название.
Подождите после завершения: строка и её клавиша должны остаться зелёными.
Откройте задачу — зелёная подсветка снимается. Затем запустите её повторно:
следующее завершение должно создать новое уведомление.
Выключите опцию и проверьте возврат native Micro, остальные слои и настройки
подсветки. Сборочные тесты не заменяют эту проверку на физическом устройстве.
С включённой интеграцией отправьте несколько сообщений и переименуйте задачу
в Codex: ошибки `EPERM ... rename` быть не должно. Открытие мышью сохраняет зелёный
статус до открытия той же задачи с макропада.
Переведите Windows в сон при включённой интеграции, затем разбудите компьютер:
названия должны восстановиться автоматически. Повторите с Entropy, свёрнутой
в трей. Также проверьте отключение и повторное подключение USB.
